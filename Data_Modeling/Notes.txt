

Data Modeling:

1. Structuring (Business Object, Clear structure for the tool)
2. 3 Parts (Tables, Relationships, and Calculations)
3. Roles (Fact - What happened, Dimension - Describes what happened)
4. Shapes (Star Schema, Snowflake Schema, Galaxy Schema)
                        * Snowflake (When Dimensions are getting bigger, split it and connect, single Fact table)
						** Galaxy (More than one Fact that are sharing the same Dimension)



USERELATIONSHIP(DAX) - A DAX function that turns on an inactive relationship for one specific calculation.

Dimensions in Disguise - Extracting Dimensions from the Fact table.

Junk Dimension - Describe A small dimension that bundles several unrelated low-level flags.

Role Playing Dimension - One dimension joined to the same fact through several relationships 
so it plays different roles. Only one is active at a time.



Fact Table:

Grain: The level of detail that one row in a fact table represents.

Multiple Facts Model:
Shared (Conformed) Dimension: One complete dimension that both facts connect to,
so we can safely compare their measures.


Row-Level Security (RLS):

1. Three levels: Table, Column, Row.
2. RLS filters the rows, the most common.
3. Static: A role per value. For small projects.
4. Dynamic: One role + DAX (USERPRINCIPALNAME()). It grows over the period.
5. Connect the security table in the right direction.
6. Ask. Secure only what's needed. Test.

Factless Fact:
Fact Table that has a lof of ID's in order to connect
to connect multiple Dimensions, it has as well dates. But it doesn't contain
any numbers (No measures).
Only tracking whether something happened or not.
